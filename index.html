About Me

I am a QA Engineer with 3+ years of experience building test automation frameworks and testing distributed, cloud-native systems. Most of my work sits where releases are hardest to trust: validating API responses and system behaviour in non-deterministic distributed environments, running on Kubernetes behind CI/CD pipelines.

I also use Generative AI as a working tool rather than a talking point. I apply prompt engineering to turn user stories into structured test scenarios, and I have built and tested a RAG system end to end to understand how LLM-backed features actually fail — where a retrieval gap hides behind a perfectly grounded answer, and why non-deterministic output needs a different kind of oracle than a string comparison.

I care about integrating AI into the QA lifecycle for faster, smarter and more reliable releases — and about being honest in writing about what a test suite does and does not prove.

Projects

Q&A Support Bot using Retrieval-Augmented Generation (RAG)

An LLM-powered support bot, built as much to study how AI systems fail as to answer questions. FastAPI serves the API; LangChain and Chroma handle retrieval; a local Llama 3.1 via Ollama generates the answers, so the whole stack runs offline at zero API cost.

The testing is the substance of it. 548 automated tests and ten distinct evaluation methods, deliberately layered cheapest-first: deterministic phrase and figure assertions with negation detection, groundedness checking, semantic similarity, retrieval metrics (Recall@k, Precision@k, MRR), adversarial and prompt-injection testing, metamorphic relations, persona-invariance (bias) testing, generated red-team attacks via Promptfoo, and LLM-as-a-judge — the last kept strictly advisory, never allowed to decide whether a build is green.

Two reproducible retrieval defects came out of the relation suites on their first run, both tracing to one root cause: a fixed similarity threshold with chunks clustered near it. One of them scored 100% groundedness while being completely wrong, because the answer was faithful to the single incorrect chunk it had been handed — which is the clearest argument I know for measuring at every boundary instead of only at the output. Both are documented with their evidence rather than quietly fixed.

CI runs 445 model-free tests in under four seconds on every push.

Tech: Python, FastAPI, LangChain, Chroma, Ollama (Llama 3.1), sentence-transformers, Pytest, Promptfoo, Postman, GitHub Actions, Docker-free local stack

View Project

Detection of Algorithmically Generated Malicious Domains

Malware families use domain generation algorithms to produce throwaway command-and-control domains faster than a blocklist can be updated, which makes this a classification problem rather than a lookup problem.

I built a stacking classifier over 11 machine-learning algorithms with a random forest as the final estimator, reaching 96% accuracy. The work was my CDAC capstone and is published with the full notebook, the serialised tuned model, and the written report and presentation — so the result can be re-run rather than just read.

Tech: Python, scikit-learn, pandas, Jupyter, ensemble and stacking methods, hyperparameter tuning

View Project

Containerised Flask API

A deliberately small reference project: a Flask service exposing GET /hello, bound to 0.0.0.0 so it is reachable from outside its container, with a Dockerfile and the build-and-run steps written out.

It exists because the gap between "the API works on my machine" and "the API works in a container someone else starts" is where a lot of environment-specific test failures come from, and it is worth having that reduced to its smallest honest example.

Tech: Python, Flask, Docker, REST
